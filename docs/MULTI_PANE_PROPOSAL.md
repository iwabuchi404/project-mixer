## 0. 前提 — 翻訳装置は変えない

**[[10_コンセプト（翻訳）]] の「翻訳装置」は差し替えない。** 本提案はコンセプトの転換ではなく、**人間→AI 方向の翻訳チャネルを1本追加する**提案である。

この確認を冒頭に置く理由は、内容がスコープ拡大に見えるため。錨が動いたと後から誤読されると、D1〜D9 の改訂根拠（翻訳説から定義上導かれるもの）が宙に浮く。**変わるのは扱えるチャネルの幅であって、装置の定義ではない。**

## 1. 変更の要旨

Phase 8 の当初仕様「2分割固定（縦または横に1回）」を、**フラットな可変ペイン**に改める。

採用理由は**単独で成立する使用実態**に置く。get_focus の将来価値は理由に据えない（§3 で位置づけを別に定める）。

| | 旧 Phase 8 | 本提案 |
| --- | --- | --- |
| ペイン | 2分割固定 | フラットな可変配列（入れ子は禁止・ソフト上限あり） |
| タブ種別の配置 | プレビュー/ブラウザは左固定 | 任意のペインへ配置可 |
| get_focus | Phase 8 後に再検討 | **Phase 8 に含めない**（§5） |
| ドラッグ&ドロップ | — | **含めない**（右クリック移動のみ） |

### 1.1 採用理由（一次観測）

現在の使用実態は **ターミナルとマークダウン文書がおよそ半々**。用途によっては文書側の滞在時間がさらに伸びる見込みがある。案B（Phase 4）で常設が1面になっているため、この往復は**タブ切替として毎回発生している**。

これは仮説ではなく本人の一次観測であり、Phase 8 を実施する根拠としてこれで足りる。

### 1.2 2分割固定を改める理由

Phase 8 の B1 は `projectEditorStates` を「1グループ」から「グループ配列」へ書き換える作業そのもの。配列にするなら要素数の上限は実装上ほぼ自由で、**2に固定する側に追加コストがかかる**。

ただし**入れ子は明確に別物**。レイアウトが木構造になり永続化コストが跳ねるため、フラット（横 N 枚 または 縦 N 枚）に限る。これは実測を待つ項目ではなく、本提案の時点で**決定**とする。上限値のみ実測で調整する（初期案 4）。

### 1.3 業界の状況（2026-08 調査）

| 製品 | プレビュー実装 | 分割 |
| --- | --- | --- |
| Cursor 3 (Glass) | webview パネル | ブラウザ/ターミナル/エディタの分割は非対応（公式フォーラム 2026-04） |
| Windsurf | Chromium フォーク | 単一プレビューパネル |
| Zed | 埋め込みブラウザ未実装 | 分割ツリーは自由（全て同一プロセス） |
| Claude Code Desktop | ネイティブ Preview パネル | 単一パネル |
| Antigravity / Devin | 埋め込まず外部ブラウザ + 録画 | 単一（D15 / [[kamox]] と同型） |

「プレビューを複数ペインに出せる製品は存在しない」。ただし理由は技術的壁ではなく、①単一パネルで需要を満たせている ②本気でやるなら Windsurf 級の投資が要る、の2点。PM は **webview の再読込を許容する政策**で②を回避する（§4.2）。

## 2. なぜ翻訳説の枠内なのか

「注意を観測する」と書くと概念の拡張に見えるため、**翻訳説から導出できることを明示する**。

D13 は `get_focus` を「翻訳の最も純粋な形 — 人間の注意そのもの（空間的・非言語的）が、エージェントの受理できる形式に変換される」と定義した。本提案が変えるのは**その注意が持てる形**だけである。

| | 単一サーフェス（現行・案B） | マルチペイン |
| --- | --- | --- |
| 注意の型 | **値**（どのタブがアクティブか） | **分布**（何が視界にあり、どれがキーボードを持つか） |
| 指差し | 「このファイル」まで | 「話しながらあの行」＝発話と空間指示が同時に成立 |
| 移動 | タブ切替履歴 | ペイン間の視線移動 |

単一サーフェスでは、注意は「アクティブなタブ」という1つの値でしかない。**並置されていない限り、指差す先と話す先が同時に存在しない。** よって「見ながら指す」という最も基本的な非言語指示が、レイアウトの側で原理的に排除されている。

翻訳装置の定義（人間の側の表現を、エージェントが受理できる形式に変換する）は変わらない。**変換元の表現が1種類増える**だけである。

### 2.1 この提案の中で最も独自性が高い部分

`hasFocus`（キーボードを保持しているペイン）と「視界にある」の分離。

> キーボードはターミナル、目はドキュメント

この状態は VSCode の active editor にも Cursor にも存在しない。単一の active な対象しか持たない設計では表現できないため。**注意の分裂を構造化データとして出せることが、ペイン数そのものより価値が高い。**

## 3. 決定案 D24: 注意は値ではなく分布として扱う

**決定（案）**: 人間の注意状態を、単一の「アクティブな対象」ではなく、**可視な対象の集合 + キーボード保持先**として表現する。メインエリアの分割は、この表現を成立させるための前提構造として位置づける。

**根拠**: §2 のとおり、翻訳説の定義から導かれる。人間の注意が実際には分裂している（見ている対象と操作している対象が異なる）以上、それを単一値に潰す表現は**翻訳として不正確**であり、装置の定義に照らして欠陥にあたる。

**帰結**:

- Phase 8 は「画面を分けたい」という UI 要求であると同時に、**この表現を可能にする構造変更**である
- `get_focus` の将来のスキーマは、単数の `file` / `terminal` ではなく**ペイン集合 + `hasFocus`** を基本形とする
- ただし **D24 は Phase 8 の完了を要求しない**。Phase 8 が完了しても D24 の実装（配信経路）は別途必要であり、§5 の未決が解けるまで着手しない

**この決定は差別化の主張ではない。** 実際にエージェントの出力を変えるかは未検証（§6）。

## 4. Phase 8 の仕様

### 4.1 ペインモデル

- `panes: Pane[]`（1個 = 分割なしの現行形を含む）
- **入れ子は禁止**。コンテナ全体の向き（縦積み/横並び）を1つ持ち、各ペインの比率を保持する
- サポートするのはフラットな横 N 枚 / 縦 N 枚まで
- ソフト上限: 初期案 4。ハードブロックではなく警告表示。値のみ実測で調整
- 分割の単位は中央エリアのみ（scratch は含めない — 旧仕様から変更なし）

### 4.2 タブ種別と配置

| タブ種別 | 配置 |
| --- | --- |
| ターミナル | 任意のペイン |
| ファイル（エディタ） | 任意のペイン |
| プレビュー / ブラウザ / 検索 | 任意のペイン（旧仕様の「左固定」を改める） |

- `<webview>` はタブに所有される。**タブを別ペインへ移すと再読込されることを仕様として明記する**（VSCode Simple Browser と同じ割り切り）。隠さない
- 再読込時、既存の `capturePreviewScroll` / `restorePreviewScroll` でスクロール位置を復元する
- 静的ファイル（md / html / 画像）は再読込の実害がほぼゼロ。localhost ブラウザタブは HMR で常時再読込のため体感差なし
- webview のライフサイクル: **表示中のタブのみ生かし、非表示は `about:blank` で破棄**（既存実装を踏襲）。メモリは「可視ペイン数 × 数十MB」で収束する

### 4.3 ターミナルの描画規律

- 非表示グループを `display:none` にすると xterm.js の寸法計測が 0 になる（Phase 4 の既知の罠）。再表示時に**全可視ターミナルへ `fit()`**
- スプリッター / ウィンドウのリサイズ時も同様

### 4.4 操作

- `pane_split`: フォーカス中のペインを分割（方向: 縦/横）。分割済みなら方向のトグル
- `pane_close`: フォーカス中のペインを閉じる。**タブは残存ペインへ移動**（タブは失わない）
- `tab_move_to_pane`: タブを指定ペインへ移動。**入口はタブ右クリックメニューのみ**
- `focus_pane`: ペインへフォーカス移動
- **ドラッグ&ドロップは本提案に含めない。** N ペインのドロップ判定は新規実装であり、右クリック移動で機能は充足する。要望が出たら別途
- レイアウトライブラリは導入しない（D10 / Phase 4 の Tab 一本化 / `projectEditorStates` との衝突理由は有効）
- スプリッター: `makeVSplitter` を一般化し縦横両方向へ対応（水平は既存 `.hsplitter` を流用）

### 4.5 コマンド定義（D19）

`pane_split` / `pane_close` / `tab_move_to_pane` / `focus_pane` を `src/commands/types.js` と `src/commands/schemas.js` の**両方**に定義する。

> **注意**: 「コマンド定義の追加漏れが起動を壊す」は [[15_Phase2.5 調整フェーズ]] で実際に起きた最大の問題。片方だけの追加は起動時に落ちる。

MCP へは pane 操作を公開しない（D11: エージェント都合の操作にあたる）。

キーボード操作（`Ctrl+1`〜`4` 等）は **D21**（キーバインドは `when` context を持つテーブル）の語彙へ追加する形とし、Phase 5 と整合を取る。

### 4.6 永続化と移行

- `layout.json` を「ペイン配列 + 向き + 比率 + 各ペインのタブ/アクティブ状態」スキーマへ更新
- 旧形式（1グループ）からの移行: 旧エントリ = 第1ペイン。起動時に自動変換
- `validateLayout`（`src/main/config-service.cjs`）を新スキーマ対応。**D18 のとおり layout.json の破損は非致命的**（リセットして継続）
- ペイン配列が single source of truth（R2 の規律を維持）

### 4.7 push の拡張（本提案に含める・0.5日）

**送信時に本文へ混ぜる情報に、可視ペインの構成を加える。**

D13-6 および D13 再改訂で push は主経路に格上げ済み。push は PM が送信経路を握っているため**呼び出し元の識別問題を踏まない**（誰宛かが自明）。エージェント側の対応も不要で全ツールに届く。

これにより、D24 の「注意は分布である」という表現が、MCP の未決（§5）を待たずに**送信時に限って**成立する。

| | 識別問題 | エージェント側対応 | 何が届くか |
| --- | --- | --- | --- |
| **push（本提案に含む）** | 踏まない | 不要 | 送信時の並置文脈 |
| `get_focus` v2（pull・含まない） | 踏む（未決） | MCP 対応 + 識別手段 | ターン中の注意変化 |

## 5. get_focus v2 を Phase 8 に含めない理由

### 5.1 呼び出し元の識別が未決

D13 再改訂は D13-4（セッション別トークン URL）を**撤回**し、`http://127.0.0.1:41001/mcp` 固定・無認証へ移行することを決めた。その正当化は明示的に条件付きだった。

> 公開する操作が `show_file`（人間に見せるだけ）に限られるため、悪用されても被害は「勝手にファイルが表示される程度」
> 将来 pull 系や書き込み系を足す場合は、認証を再検討する

`get_focus` v2 は pull 系そのものであり、この条件に正面から当たる。具体的に2つ穴が空く。

1. **どのプロジェクトのエージェントが呼んだか分からない。** D13 再改訂が「返すべきでない」と明記した「別プロジェクトのエージェントへ人間の注意を返す」が、無認証の固定 URL では既定動作になる
2. **危険度が `show_file` と異なる。** 同一マシンの任意プロセスが、開いているパス・選択行・scratch 本文を読める。「勝手にファイルが表示される程度」では済まない

**2026-08-25 時点で、無認証・固定 URL 化そのものが未実装**（doc16）。つまり**選択肢はまだ閉じていない**。ここは Phase 8 の一項目ではなく、**D13 の再々改訂**として別に扱う。

### 5.2 動機の多くは push で満たされる

「人間が『この設計でいい？』と聞く」という典型例は**送信時**の場面であり、§4.7 の push 拡張で届く。pull にしかできないのは「ターン中に人間が見ているものが変わったとき」に限られる。

### 5.3 スナップショットか遷移か、が未決

D24（§3）が示唆する価値の中心が**遷移**（エージェントの出力が出た数秒後にドキュメントペインへ目が移った、等）にあるなら、必要なのは要求応答の `get_focus` ではなく**イベントログとその読み出し**である。この選択が決まらないうちにスキーマを固定すると、後で作り直すことになる。

**結論**: Phase 8 完了後に、①識別と認証 ②スナップショットか遷移か の2点を決めてから着手する。

以下は**いずれも実測ではなく体感に基づく**。今回は計測を行わない判断をした。
