## なぜキーバインドが先か

検索は4種とも新しいキーを要求する。D21 の根拠がそのまま効く。

> `Ctrl+F` と `Ctrl+Shift+F` を「ターミナルにフォーカスがあるか」で切り替える際、**ハンドラ内に条件文を書くと D10 で消したはずの構造が戻る**。

現状のキー処理は 8箇所以上の `keydown` リスナーに分散し、`e.ctrlKey && e.key === 's'` 形式の条件文が埋まっている（`renderer.js:2537` / `2541` / `2545` / `2550` / `2905` / `3360` / `3521`）。**ここに検索の4種を足すと、後で全部書き直しになる。** Phase 3 でコマンド層を先に作ったのと同じ関係。

### 規律

> **ターミナルにフォーカスがあるとき、PM はキーを横取りしない。例外は `Ctrl+Shift+*` 系のみ。**

シェルが使うキーは潰せない — `Ctrl+F`（forward-char）、`Ctrl+P`、`Ctrl+R`（逆方向検索）、`Ctrl+S`（XOFF）、`Ctrl+B`（tmux prefix）。上表の `Ctrl+F` に `terminalFocus` が入っていないのはこのため。

Electron のメニューアクセラレータは xterm より先に消費するため、**`registerAccelerator: false` の方針を維持する**（A8 のレビューで確定済み）。

## S1. ツリーフィルタ（群B-1）— 2〜3日

### 仕様（`12_v2アーキテクチャ` で確定済み・変更しない）

- [ ] **部分一致。fuzzy にしない**
  - fuzzy は `avue` が `App.vue` にも `assets/value.ts` にも当たり、構造を無視して散らばる。**再現(recall)のための道具で、再認(recognition)を捨てる** ＝ ツリーを選んだ理由そのものを壊す
- [ ] 一致したファイルを**祖先フォルダごと**表示し、一致を含まないフォルダは非表示
- [ ] フィルタ中は自動展開
- [ ] **クリア時にフィルタ前の開閉状態を復元する**（これがないと全展開のまま残り、元より悪化する）
- [ ] アクティブなプロジェクトのみを対象にする
- [ ] 50〜100ms デバウンス
- [ ] 専用キーでフォーカス、`Esc` でクリア

### 本体は UI ではなくインデックス

現在のツリーは**遅延読み込み**で、展開操作のたびに `fs:readDir` を1階層ずつ呼んでいる（`renderer.js:700` / `renderer.js:825`）。このままではフィルタが**展開済みノードにしか効かない**。

- [ ] `fs:indexTree` IPC を追加する（再帰 walk、`main.js` の `ipcMain.handle` パターンに従う）
- [ ] **除外パターンを1箇所に切り出す。** 現在 `.git` / `node_modules` が `main.js:669` にハードコードされており、インデックスと `fs:readDir` で二重定義になる
- [ ] 構築タイミング: プロジェクト選択時に非同期構築。`#tree-reload-btn` で再構築
- [ ] 無効化: `fs:createFile` / `fs:createDir` / `fs:deleteFile` の経路でインデックスを更新する
- [ ] **ファイル数と構築時間を計測して記録する。** 大規模リポで数万件になる場合、この数字が S2 とパレットの設計前提になる

> このインデックスはパレット（群B-2）でも再利用する。本フェーズで作っておけば、パレット着手時の工数が下がる。

### D23 との関係

除外パターンは D23 で「グローバル設定」に置くと決まっているが、**設定機構は本フェーズの範囲外**。今回は定数の共通化までとし、設定化は D23 の着手時に行う。

### 検証

- [ ] フィルタ結果に**未展開フォルダ配下のファイルが含まれる**こと（インデックスが効いている証拠）

## S2. プロジェクト内テキスト検索（群B-3）— 1〜2日

### 方式（D22 の訂正どおり）

当初 ripgrep 同梱かインデックスが必要としていたが、**`git grep` で安く作れる**。git は D16 で既に依存に入っており、`.gitignore` を尊重し、十分速い。**同梱物ゼロ、インデックス不要。**

- [ ] `rg` があれば優先し、無ければ `git grep` にフォールバックする（`command:check` の既存機構を流用できる・`main.js:516`）
- [ ] **`git --no-optional-locks grep` を使う**（D16 の非阻害ルール1）
  - `git grep` は index に書き込むため、エージェントや husky の commit 中に叩くと `.git/index.lock` を奪い合い、**相手のコミットを失敗させる**
- [ ] git 管理外のファイルは引っかからないため、`--untracked` を付けるか `rg` との挙動差を UI に明示する
- [ ] `search:text` IPC を追加し、`child_process.spawn` で行単位にストリームする（大量ヒットで固まらせない）
- [ ] 結果件数に上限を設ける（例: 500件で打ち切り、打ち切った旨を表示）

### 結果の出し先

**中央タブに「Search」タブとして開く。** ツリー下に常設パネルを作らない。

Phase 4 の判断（常設すべきでないものを常設しない / 常設は「ターミダル or いま見ているもの」の1つだけ）に従う。検索結果は**確認時にだけ見るもの**であり、随時側に属する。

- [ ] 結果行のクリックで既存コマンドに載せる: `preview_open(path)` → `preview_reveal(line)`
  - **この経路は既に実装済み**（`renderer.js:4120` / `renderer.js:4189`）。新規に書くのは結果リストの UI だけ
  - CM6 導入後は `preview_reveal` の委譲先がエディタに変わるが、**S2 側の変更は不要**

### コマンド定義

- [ ] `search_text` / `search_text_open` を **`src/commands/types.js` と `src/commands/schemas.js` の両方**に定義する（D19: Zod 検証）

> **注意**: A8 のレビューで「コマンド定義の追加漏れが起動を壊す」が最大の問題として記録されている。`register()` は未定義名で throw し、`renderer.js` のトップレベル呼び出しのため**例外以降が全て実行されない**。片方だけの追加は空ウィンドウになる。

### MCP へは公開しない

D11 の判定（「これは Shared View に載るか」）で落ちる。検索はエージェント自身の作業のための操作であり、人間に見せるためのものではない。エージェントは既に `Grep` / `Bash` を持っている。

### 検証

- [ ] `rg` 無し環境で `git grep` にフォールバックすること
- [ ] `--no-optional-locks` が付いていること（コマンド組み立ての単体テスト）
- [ ] 大量ヒット（1000件以上）で UI が固まらないこと
- [ ] 結果クリックで該当行が表示されること

## リスクと注意

| 項目 | 内容 |
| --- | --- |
| **ターミナルのキーを削る** | 本フェーズは最もキーを増やす。`when: terminalFocus` を安易に足すと機能後退する。A8 で実際に起きている |

| **S3 の前提** | CM6 未導入で着手すると textarea 用の検索を作って捨てる |
| **`findInPage` のハイライト残留** | `stopFindInPage` を呼ばないと、タブを切り替えてもハイライトが残る |
